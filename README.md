# Задание 1. Анализ и планирование

### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут удалённо включать/выключать отопление в своих домах.
- Система поддерживает функцию регистрации датчика при включении.

**Мониторинг температуры:**

- Пользователи могут просматривать текущую температуру в своих домах через веб-интерфейс.
- Система получает данные о температуре с датчиков, установленных в домах.

### 2. Анализ архитектуры монолитного приложения

Перечислите здесь основные особенности текущего приложения: какой язык программирования используется, какая база данных, как организовано взаимодействие между компонентами и так далее.

- Монолитная архитектура
- Go
- СУБД Postgres
- Синхронная обработка запросов
- Существующий монолит можно масштабировать горизонтально, но есть ограничения: синхронная обработка запросов, общая PostgresSQL, внешний API
- Развертывание требует остановки всего приложения

### 3. Определение доменов и границы контекстов

- Домен: управление системой отопления
  - поддомен: управление устройствами
    - контекст: устройства отопления
  - поддомен: мониторинг температуры
    - контекст: температурный мониторинг

### **4. Проблемы монолитного решения**

- Данный монолит сложно масштабировать
- Общая PostgresSQL - если БД недоступна то функционал приложения теряет смысл
- API (синхронная обработка запросов) - может не отвечать или отвечать с задержкой
  - внешний сервис не отвечает - запросы копятся
  - при нагрузке одновременных запросов большой расход ресурсов
